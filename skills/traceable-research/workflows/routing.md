# 路由

按用户诉求选**恰好一条**工作流。选定后只读该文件。

| 用户诉求的信号 | 工作流 |
|---|---|
| 「检索一下…的文献」「写文献综述」「这个方向研究现状如何」「有哪些空白」「帮我列相关论文」 | [`literature.md`](literature.md) |
| 「调研一下市场」「有哪些竞品/厂商」「价格如何」「政策要求」 | [`market.md`](market.md) |
| 「把文献和市场的结果合起来」「两稿合并」「写成一份能交差的材料」「交叉看一下」 | [`cross-merge.md`](cross-merge.md) |

## 判定顺序

1. 诉求同时含文献与市场 → `cross-merge.md`（它内部会调两条线）
2. 只涉文献 → `literature.md`
3. 只涉市场 → `market.md`

## 前置缺失时

- **文献线需要**：项目根可达、`.env` 有可用的 LLM 端点；若主题含中文，还需要
  cnki-mcp 已初始化（未初始化则提示用户先跑 `uv run cnki-mcp init`，本 Skill 不代做登录）。
- **市场线需要**：能出网。ddgs 回退走 `search.brave.com`，受限网络下会超时；
  这种情况不要反复重试，改用 Tavily（`TAVILY_API_KEY`）或告知用户换网络。
- **合稿需要**：两条线的产物都已落盘且各自过了产物核验。

缺前置就说明缺什么、停哪条路由，不要绕过。
