# traceable-research Skill

本 Skill 是**路由 + 全局纪律**层：三条检索工作流的细则在 `workflows/`，
领域知识在 `references/`，核验脚本在 `scripts/`。检索能力由
[academic-research-agent](https://github.com/cyl385844997/academic-research-agent)
项目代码提供，本 Skill 不重复实现它。

## 强制加载顺序

**硬规则——路径先于命令**：把本文件所在目录记为 `SKILL_DIR`，之后所有相对路径
都用 `${SKILL_DIR}` 展开。**不要 `cd`、不要用当前工作目录、不要假设仓库检出位置。**
拿不到 `SKILL_DIR` 就问，不要搜索或猜。

1. 读本文件。
2. 运行 `python "${SKILL_DIR}/scripts/preflight.py"`。非零退出即停止本 Skill：
   不修复、不绕过。该脚本检查项目路径、`.env`、Python 依赖与护栏自测。
3. 读 [`workflows/routing.md`](workflows/routing.md)，选定**恰好一条**工作流。
4. 只读所选工作流文件及其显式引用的 `references/`。

| 需求 | 工作流 |
|---|---|
| 检索文献、写文献综述、判断研究空白 | [`workflows/literature.md`](workflows/literature.md) |
| 市场格局、竞品、产品与政策调研 | [`workflows/market.md`](workflows/market.md) |
| 两路结果合成一份带交叉讨论的材料 | [`workflows/cross-merge.md`](workflows/cross-merge.md) |

**硬规则——只读所选路径**：路由完成后不得再加载另一条工作流的细则。
需要第二条线时，先把第一条的产物落盘并告知用户，再重新走路由。

## 术语表

一个词只有一个含义；出现歧义时以本表为准。

| 术语 | 含义 |
|---|---|
| **资料员** | 由代码承担的采集角色：检索 → 解析 → 去重 → 分级/质量过滤 → 生成 TSV 与注入上下文。**不经 LLM** |
| **研究员** | 由 LLM 承担的角色：只基于注入的真实数据做分析与撰写 |
| **检索员 / 侦察员** | **本项目已删除的角色**。它在无工具时会凭记忆编一份清单或伪造检索过程，是编造引用的源头 |
| **两道闸门** | `sanitize_report_urls`（URL 白名单）+ `sanitize_report_citations`（DOI 白名单），写稿后运行 |
| **带外核验** | 用 `scripts/verify_report.py` 对任意报告独立抽检，不依赖项目进程 |
| **可溯源** | 报告中每条引用都能在白名单（检索缓存 / 文献表）里找到对应记录。**无白名单不得声称可溯源** |
| **A/B/C 分级** | 市场线来源可信度：A 官方/学术，B 主流媒体，C 社区/商业平台。C 级仅作旁证且须标「待核实」 |
| **白名单冲突** | 报告引用了不在当前缓存里的 DOI/URL。先判断是「补检后未同步缓存」还是「真编造」，不要直接改报告 |

## 全局执行纪律

1. **串行执行**——按工作流给定的步骤顺序走，完成一步再进下一步。
2. **闸门即停**——凡标 ⛔ 的核验项，先跑完再往下；不通过就停下来报告，不要自行修复产物。
3. **不跨阶段打包**——文献线/市场线没跑完，不要提前做合稿；合稿依赖两线产物落盘。
4. **入口先验**——进任何一步之前先确认该步的前置条件齐备。
5. **不做投机执行**——不提前准备后续步骤的产物。
6. **确定路由**——`routing.md` 能判定时不要反问用户；若某条路由的前置缺失，说明缺什么并停止该路由。
7. **在 owning 层修复**——失败时在最浅的那一层修（报告文字问题改报告、护栏问题改代码、
   环境问题改环境），修完从工作流声明的断点继续。**不要静默降级**。

## 全局交付纪律

- 「证据支持 / 不支持 / 缺口」分开写；**不给「建议立项」类结论**——判断权在人不在 Agent。
- A/B/C 分级与「待核实」「证据不足」等限定词**原样保留**，转述时不得升格。
- 条数、被引数、年份等数字必须来自产物，不得凭印象填写。
- 涉及内部实测值时按用户的脱敏口径处理。

## 仓库兼容性

- 本包是工作流/技能，不是应用脚手架：不要在 Skill 目录内造 `tests/`、
  `worktrees/`、分支流程等通用工程结构。
- 运行时所需的工作流、参考、脚本文档**全部留在本 Skill 目录内**；
  项目级文档（`docs/`、README）可以指向本包，本包运行时不依赖项目级文档。
- Windows 上若 `python3` 不可用，改用 `python` 执行同一条命令。
- 项目未安装时：先 clone
  `https://github.com/cyl385844997/academic-research-agent`，再设 `ARA_HOME`
  指向其根目录，然后重跑 `preflight.py`。

## 绝不做的事

- 不把付费库（知网/万方/维普）写爬虫——无公开 API 且禁止爬虫，合规红线
- 不把 `.env`、API key、记忆库内容提交进任何仓库或转发
- 不在无白名单的情况下声称「引用可溯源」
- 不因为「报告已经生成了」就跳过产物核验
- 不把「检索返回 0 条」这类断言当事实——那可能是被删除的侦察员角色伪造的检索
