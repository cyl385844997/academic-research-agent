# 学术 + 市场融合调研 Agent —— v0.2 规格

> 版本：v3（重大修订：定位线整路移出 v0.2）
> 基线：v0.1.1（tag `2705926604`，含记忆 TTL 机制）
> 状态：用户已裁定，可按第 6 节实施顺序开工
>
> **v3 修订说明（2026-10-12，用户裁定 A：整路砍）**：原「定位线」（机会定位矩阵 +
> 权重打分 + 建议/观望/不建议判断）整路移出 v0.2，推迟到 v0.3 备选。
> 核心理由：**第三问「该不该我们做」的信息优势在立项会的人这边，不在 Agent 这边**——
> 内部条件（有什么装置、预算权限、红线）人不需 Agent 对照；Agent 的优势在外部证据
> （四库系统检索、去重、来源分级）。让 Agent 干它没优势的活，人退化成盖章的；
> 且 Agent 对 250 万级投入说「建议立项」属于越权——错了没有问责主体。
> **先用真实立项会验证需求，再建基础设施**（结构从需求反推，第二次应用）。
> 定位线的全部设计文档保留在案（`docs/company_profile-schema-v1.md`，已标暂缓），
> 脱敏防护作为防御机制保留，不随功能下线而拆除。

## 1. 定位（最高优先级约束）

**公司内部科研人员的技术调研工具**，不是高校文献综述工具、不是通用市场调研工具。

服务两个判断，且只服务这两个：
- **技术可行性**（学术线回答「能不能做」）
- **市场价值**（市场线回答「值不值得做」）

第三个判断——**「该不该我们做」——由立项会的人做，Agent 不碰**。

输出对象是**立项会决策者**。Agent 交付证据，人做裁决；所有输出服务于
「要不要立项 / 怎么切入 / 值不值得投入」，但结论一栏永远留给人。

## 2. 两条线的关系

学术线与市场线**不是并列拼接，是交叉**：

```
学术线（采集）→ 技术成熟度证据     → 回答「能不能做」
市场线（采集）→ 竞争格局证据       → 回答「值不值得做」
                    ↓ 交叉（技术路线为主键）
              每条路线一张证据卡 → 交立项会裁决
```

- 单独看任何一条线都会误判
- 两条线必须以**「技术路线」为主键**组织，才能交叉
- 交叉的产物是**可横向对比的证据卡**，不是结论——对比是事实，结论是裁决

**人工对照清单（定位线的替代物）**：报告附一页「人工对照清单」，提示立项会
逐条核对三问——能力缺口、预算档位、红线/主业符合性。清单只提示「该核对什么」，
**不读档案、不代答**。这三问的答案在人手里，Agent 替他们查自己的家底没有信息优势。

## 3. 可信度必须分级（不可妥协）

两条线数据源性质不同，**不能用同一套可溯源标准**：

| 线 | 数据源 | 可溯源标准 | 可信度等级 |
|---|---|---|---|
| 学术线 | 权威学术库 | DOI 可核 | 🟢 可核 |
| 市场线 | 网页/新闻/官网/专利库 | 来源 URL + 抓取日期 + 来源类型 | 🟢官方 / 🟡二手 / 🔴推断 |

铁律：
- 学术线：文献表由代码生成，LLM 绝不参与（沿用 v0.1 可溯源铁律）
- 市场线：做不到 DOI 级就明确承认。每条信息必须带来源 + 日期 + 可信度等级
- **绝不用学术线标准要求市场线**——否则逼 LLM 编造来源，制造信任黑洞
- 市场信息无来源，宁可不写，不许编

## 4. 必须呈现「不做」的证据

Agent 不裁决，但**不许只写好话**。原来「定位矩阵必须有观望/不建议行」的纪律，
转换为对证据呈现的对称性要求：

- 每条路线必须同时呈现**支持信号与反对信号**（成熟度低、竞争饱和、专利密集、
  头部厂商已占位，都是事实，找到就必须写）
- 一页纸摘要里「风险与排除信号」是必备段落，不许省
- 人工对照清单里「排除项」是必填栏——立项会要明确记录「不做/观望」及理由，
  一份全是「推荐」的会议纪要不是 Agent 的锅就是会议的锅，但 Agent 要先保证
  自己交付的证据里排除信号没被藏起来

- `knowledge/company_profile.example.yaml`（模板，在库）
- `knowledge/company_profile.yaml` 真实文件 gitignore（在库规则）
- `scripts/check_sensitive.sh`（防真实文件被 track，在库）
- `docs/company_profile-schema-v1.md`（字段定义 v1.0 定稿，**已标暂缓**）

v0.3 启动条件（两条同时满足才值得建）：
1. 至少一次真实立项会跑完 v0.2 流程
2. 会上出现明确信号：人肉对照能力/预算/红线「太痛」或「漏过」

若启动，v1.0 schema 直接复用，但**消费方式从「打分输入」改为「对照基准」**——
Agent 摆事实（路线要求 ↔ 档案能力，有/部分有/没有 + 缺口文字列），仍不下结论。

## 6. 实施顺序（5 步，不可跳）

1. **定死两条线的统一对比维度**（表格列定义）。注意性质变化：这不是给机器消费的
   接口（定位线没了），是**给人横向对比的格式**——每条路线在两张表里占同一行位置，
   列名跨线对齐（如「技术路线」列两张表都有）。格式没定死就动手，容易写成
   「能跑但结构不对」，照样返工。
2. 改造学术线：代码采集（已有四通道）→ 单次「标注/聚类」LLM 调用。
   **一次改造到位，不先写三角色再砍**——「角色」概念一旦进代码，即使后面砍，
   prompt 里的 role 定义/任务描述残留清理成本更高。
3. 改造市场线：保留多维检索 + 来源分级，加专利 `coverage` 标记。
4. 改输出层（见第 10 节）：证据卡 + 人工对照清单 + 一页纸摘要。
5. 改 main.py 串起来；可选加项：知网检索台账（断点续跑）+ RIS 引用导出。

**基线已就位**：v0.1.1 tag 已打，v0.2 改动大可回滚。

## 7. Crew 形态（2 次 LLM 调用）

```
学术线：代码采集 → 单次「标注/聚类」LLM 调用 → [{路线, 成熟度, 关键文献, 信号, evidence_sentence}]
市场线：代码采集 → 单次「标注/聚类」LLM 调用 → [{路线, 竞品, 专利, 动态, 来源, 可信度, coverage}]
```

关键约束：
- 学术线「标注」是**分类 + 抽取证据二合一**，必须引摘要原句（成熟度标签附
  `evidence_sentence`），不是纯分类
- 两次调用职责清晰，每次输入输出都是结构化数据
- 检索员角色删除：采集全代码化，不让 LLM 复述代码已经拿到的结果

## 8. 技术路线对齐（主键难点）

路线标签从 `domain_lexicon.py` 术语表派生，LLM 只能贴表内标签 + 一个「其他」。
中英对照与同义词已在词典维护，压掉大部分对齐误差。

- **「其他」必须可审计**：单次跑完「其他」占比 >30% → 报警，说明术语表覆盖不够。
  「其他」变垃圾堆就失去对齐能力。
- **术语表带版本**：路线标签一旦定下，历史报告的路线名不能变。改表时旧报告仍能
  按旧版本解析——为了「跑第二次能和第一次横向对比」，这是公司科研核心用法。

## 9. 专利检索降级

v0.2 市场线 = Web 检索（Tavily/DuckDuckGo）+ 从结果抽专利信息，**不建 `patent_tool.py`**。
专利列允许「信息不足」，不硬编。

区分两种「信息不足」，措辞不同防误判：
- **「检索了，没有相关信息」** → 可能真没有，也可能检索词不对
- **「检索工具覆盖不到」** → 明确能力边界

市场线产出给专利字段加 `coverage: full / partial / none` 标记。

## 10. 输出层

```
reports/
├── decision_summary.md          # 一页纸决策摘要（首页，给领导看）
├── evidence_cards.md            # 证据卡：每条路线一张，支持/反对信号对称呈现
├── human_checklist.md           # 人工对照清单：能力/预算/红线三问 + 排除项（人填）
├── academic_report.md           # 学术证据报告
├── academic_references.tsv      # 文献表（代码生成，DOI 可核）
├── market_report.md             # 市场证据报告
├── market_sources.tsv           # 来源清单（URL + 日期 + 可信度）
└── raw/                         # 原始数据附件
```

一页纸决策摘要结构（注意第 5 项）：
1. 本次调研范围与检索方式
2. 各路线证据摘要（一段一个路线）
3. 支持信号汇总
4. 风险与排除信号（必备，见第 4 节）
5. **结论区：留空，标注「以下由立项会填写」**——Agent 不填做/观望/不做

## 11. 验收标准

**学术线**
- 文献表由代码生成，DOI 抽检 100% 可核
- 每条文献有「技术路线」「成熟度」标签，且成熟度有摘要原句依据

**市场线**
- 每条信息有来源 URL + 抓取日期 + 可信度等级
- 无来源信息被剔除，不进报告

**证据对称性（原定位线验收的转换）**
- 抽查任一路线：反对信号与支持信号都检索过、都呈现了
- 「风险与排除信号」段落在每份摘要中存在且非空（可以是「未发现」，不许缺段）

**人工对照清单**
- 三问（能力/预算/红线）逐条在列，附填写空位
- 排除项栏存在——清单本身要提示「不做/观望」也是合法结论

**反例（做错了的样子）**
- 「综上所述，该方向前景广阔，建议关注」→ 废话
- 只列机会不列风险 → 这是招商材料，不是调研
- 市场信息无来源仍写进报告 → 破坏可信度
- Agent 在摘要结论区填了「建议立项」→ 越权，直接打回

## 12. 禁区（不要做）

- 不要把两条线各写一份报告再拼一起 → 必须交叉
- 不要用学术线溯源标准要求市场线 → 逼 LLM 编来源
- **不要让 Agent 输出立项结论（做/观望/不做/建议）→ 越权，这是 v3 的核心裁定**
- 不要把「我方条件」档案偷偷加回 v0.2 → 要加先过第 5 节的启动条件
- 不要动 v0.1 可溯源铁律 → 文献表仍由代码生成
- 不要为「看起来完整」保留散文式市场报告 → 市场部分必须结构化
- 不要引入新的多角色抽象「显得高级」 → 能用代码做的就用代码
- 不要把 company_profile.yaml 真实文件提交进 public 仓库（防御机制仍在）
