# company_profile 字段定义 v1（待审）

> 状态：**待用户审查**。审查通过 + 真实内容实战检验后，才冻结为 v1.0。
>
> 设计原则：**从定位线需求反推，不由样本归纳**。每个字段必须能回答「定位线的哪一步需要它」；答不出来的，要么删，要么标待审。本文档同时列出**已淘汰字段**，展示删减纪律。

---

## 1. 为什么顺序必须是「先字段定义、后填内容」

company_profile.yaml 是定位线的硬依赖：结构一动，定位线的输入解析、适配度打分、记忆库 dynamic 块全跟着动。若用第一份真实样本归纳结构，结构会被该样本的领域绑架——样本里有「污水厂渠道」就长出渠道字段，下一份「药企客户」样本又要求改结构。这是归纳法的天然缺陷：**下一个项目总能覆盖不到**。

演绎替代：定位线需要算什么 → 必须吃什么输入 → profile 必须提供什么字段。完备性由需求保证，不由样本碰巧覆盖到。

**附带区分：结构 vs 内容。** 字段组、层级、类型 = 结构，一次冻结，领域无关；字段的值域、枚举值 = 内容，允许领域内扩展（如 strategic_focus 的值域随术语表增长登记新标签，走记忆 pending 流程）。用户「药企」例子暴露的正是内容层扩展需求，不应靠改结构解决。

## 2. 反向核对表：定位线每步吃什么输入

这是本文档的核心。审查时请逐行核对「profile 字段」列是否完备。

| 定位线步骤 | 计算什么 | 输入来自哪里 | profile 字段 |
|---|---|---|---|
| S3 适配度 | 路线要求的能力 vs 我方能力 | 能力**要求**：学术线输出（非 profile） | `capabilities` |
| S3 适配度 | 能力差距能否弥补 | 协作策略偏好（外协/联合研发是否接受） | `constraints.external_collab` |
| S4 投入可行性 | 预计投入 vs 可承受上限 | 投入**估计**：学术/市场线输出（非 profile） | `constraints.budget_band` / `constraints.staff_band` |
| S4 投入可行性 | 装置规模是否够路线用 | 路线**所需**规模：学术线输出 | `capabilities.equipment_ceiling` |
| S5 战略契合 | 路线是否落在主业内 | 路线标签 vs 主业清单（值域与术语表同源） | `strategic_focus` |
| S5 战略契合 | 路线是否触碰红线 | 否决项清单 | `exclusions` |
| S5 转化可行性（**条件必需**） | 路线产出形态是否有承接方 | 仅当矩阵含此维度才需要 | `application_scenarios` |
| S6 权重分配 | 各维度打分的权重 | 本次决策类型决定权重表 | `decision_context.decision_type` |
| S7 判断门槛 | 「建议 vs 观望」的确定性门槛 | 风险偏好 | `decision_context.risk_posture` |

**核对结论**：9 步输入依赖，6 组字段全覆盖，无遗漏即结构完备性成立。

## 3. 字段定义

### 3.1 `strategic_focus` 主业方向清单

- **定位线哪一步需要**：S5。路线标签 ∈ strategic_focus → 正常打分； ∉ → 降级或排除。
- **形态**：字符串列表。**值域 = domain_lexicon 路线标签体系的子集**，禁止自由文本（自由文本导致「水处理」匹配不上「污水资源化」）。新方向先登记进术语表，再引用。
- **static / dynamic**：static（主业调整以年计）。
- **敏感度**：L1。主业方向基本是公开信息（官网、年报）。
- **填法**：每条 = 一个术语表标签，如 `- 污水资源化`（值以术语表为准，此处仅为格式示意）。

### 3.2 `capabilities` 现有能力清单

- **定位线哪一步需要**：S3 适配度、S4 装置规模核对。
- **形态**：结构化列表，每项含：
  - `name`：能力名（值域与术语表/能力词表同源）
  - `scale`：规模或水平（装置写 m³/d 量级，实验能力写可测指标类别）
  - `evidence_ref`：证据的**本地文件路径**（设备清单、资质证书），路径不入库真实性由本地保证，仓库里只写相对路径占位
- **static / dynamic**：static 为主（能力建设慢）；新增装置时手动追加。
- **敏感度**：L2。能力清单本身就是竞争情报，规模写**数量级**（`10^2 m³/d` 级别），不写精确值。
- **结构 vs 内容**：结构（name/scale/evidence_ref 三键）冻结；能力项的枚举值随领域扩展。

### 3.3 `constraints` 约束块

- **定位线哪一步需要**：S3（协作策略）、S4（预算/人力上限）。
- **子字段**：

| 子字段 | 步骤 | 形态 | static/dynamic | 敏感度 |
|---|---|---|---|---|
| `budget_band` | S4 | 枚举：`<50万 / 50-200万 / 200-500万 / >500万` | **dynamic**（随年度预算变） | L2 区间 |
| `staff_band` | S4 | 枚举：`≤2人 / 3-5人 / >5人`（可投入本课题的全职当量） | **dynamic** | L2 区间 |
| `external_collab` | S3 | 布尔 + 可选说明（接受外协/联合研发与否） | static | L1 |
| `timeline_expectation` | S4 | 枚举：`≤1年 / 1-2年 / 2-3年 / 不限` | **dynamic** | L1 |

- **dynamic 判定标准**（写入文档，防凭感觉分）：字段值变化频率 × 变化是否改变定位结果。两者皆高 → dynamic；否则 static。budget_band 年年变且直接改变 S4 → dynamic；external_collab 几乎不变 → static。

### 3.4 `decision_context` 决策语境块

- **定位线哪一步需要**：S6 权重、S7 门槛。
- **子字段**：

| 子字段 | 步骤 | 形态 | static/dynamic | 敏感度 |
|---|---|---|---|---|
| `decision_type` | S6 | 枚举：`中试立项 / 示范工程 / 论文选题 / 标准预研 / 长期跟踪`。定位线内置权重表：如「中试立项」→ 成熟度权重↓、专利壁垒权重↑；「论文选题」→ 学术新颖性权重↑ | **dynamic**（每次立项可能不同） | L1 |
| `risk_posture` | S7 | 枚举：`保守 / 平衡 / 进取`。决定「建议 vs 观望」的确定性门槛 | **dynamic** | L1 |

- **为什么是 dynamic**：决策语境每次立项都可能不同，而 S6/S7 直接消费它——这正是「company_profile 分 static/dynamic」的存在理由：static 错了一直错，dynamic 错了下次改。

### 3.5 `exclusions` 红线 / 否决项清单

- **定位线哪一步需要**：S5。命中即「不建议」，无需后续打分。
- **形态**：列表，每项 = {`label`（术语表标签或关键词）、`reason`（一句话）}。
- **static / dynamic**：**dynamic**（历史否决记录随立项累积，且本身是高价值决策痕迹）。
- **敏感度**：**L3**。可能涉及具体历史项目名、人名。处理方式见第 5 节待决项 D-1。
- **联动**：exclusions 的累积走记忆库 pending 流程（用户已确认的机制）——评审会上新否决一条 → 进 pending → 人工确认后写入 profile.dynamic。

### 3.6 `application_scenarios` 应用场景 / 转化对象清单（条件必需）

- **定位线哪一步需要**：S5 转化可行性——**仅当**机会定位矩阵含「转化可行性」维度才需要。
- **形态**：字符串列表，自由文本（应用场景天然领域相关，不做值域约束）。
- **static / dynamic**：static 为主。
- **敏感度**：L2（客户/渠道信息属商业敏感）。
- **为什么标条件必需**：这是「样本绑架」最高发区——「有污水厂渠道」样本会诱使结构长出渠道字段。按需求反推：字段存在与否取决于定位线**是否把转化维度纳入矩阵**，这是第 6 步定位线设计时的决策（待决项 D-2），不由样本决定。

## 4. 已淘汰字段（删减留痕）

按「定位线哪一步需要它」审查，以下字段**淘汰**：

| 淘汰字段 | 淘汰理由 |
|---|---|
| `organization_meta`（公司规模、性质、人数） | 答不出定位线哪一步需要。组织差异通过 `decision_context` 表达，不需要独立字段 |
| `business_model`（商业模式） | 同上。商业模式影响的是投入回报判断，已在 constraints 与决策语境中间接覆盖 |
| `industry`（所属行业） | 与 strategic_focus 冗余；且行业是单值标签，装不下多主业 |

> 淘汰标准供审查复用：**任一字段答不出「定位线的哪一步需要它」，即淘汰候选**。

## 5. 敏感度分级与脱敏规则

| 级别 | 含义 | 填法 |
|---|---|---|
| L1 | 公开或半公开信息 | 直接填真实值 |
| L2 | 竞争敏感但定位线必须要 | 填区间 / 数量级，不写精确值 |
| L3 | 高敏感（历史决策、客户名） | 见待决项 D-1 |

## 6. 待用户决定项

- **D-1（L3 字段处理方式）**：exclusions 的 reason 可能含敏感名。选项：
  - a) 写代号 + 本地另放一份不入库的映射文件（profile 运行时两文件合读）
  - b) 只写通用理由（「已有同类项目被否决」），细节靠人脑
  - c) 接受写入（profile 本地文件本来就不入库，泄露风险只在机器丢失）
  - 倾向 **a**：定位线打分需要区分不同否决理由的权重时，代号仍可用。
- **D-2（转化维度是否纳入矩阵）**：决定 `application_scenarios` 升级为必填还是删除。纳入则 v0.2 定位线多一维打分；不纳入则删字段，保持矩阵精简。
- **D-3（decision_type 权重表）**：五类决策类型 × 五维打分的权重表由谁定。选项：定位线代码内置（可审计、改代码即改权重）/ 写进 profile（灵活、但变成人工调参）。倾向**代码内置**——权重是方法论不是数据。

## 7. 审查清单（用户视角，只看三件事）

1. **漏**：对照第 2 节反向核对表，逐行问——定位线这步的输入，profile 真的够吗？特别是 S3 适配度：路线能力要求 ↔ 我方能力的匹配粒度是否够细？
2. **冗余**：对照第 4 节淘汰标准，逐字段问——这个字段定位线哪一步用？（本次定义已自审一轮，淘汰 3 个）
3. **跨领域压力测试**：想象下一个项目是完全不同领域（如药企）。哪格会崩？
   - 结构层（字段组）：应不崩——六组字段是领域无关的
   - 内容层（值域）：strategic_focus / capabilities 的值域需要登记新标签——这正是「结构/内容分离」要兜住的场景。若你认为内容层扩展走术语表登记太慢，此处提出，我们讨论是否要在 profile 里加 `domain_aliases`（领域别名映射）字段
