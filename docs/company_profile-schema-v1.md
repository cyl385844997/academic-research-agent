## 1. 设计原则

company_profile.yaml 是定位线的硬依赖：结构一动，输入解析、适配打分、记忆库
dynamic 块全跟着动。若用真实样本归纳结构，结构会被样本的领域绑架。演绎替代：
定位线需要算什么 → 必须吃什么输入 → profile 必须提供什么字段。

**结构 / 内容分离**：字段组、层级、类型 = 结构，一次冻结；值域、枚举值 = 内容，
随术语表登记扩展。下一个项目（如完全不同领域）走内容层扩展，不改结构。

## 3. 字段定义

### 3.0 必填性规则（审查清单第 4 项的直接产物）

**决策类型不只改权重，还改字段必填性。** 「立项」要现有能力，「选型」要产线兼容性，
「申请专利」要现有专利池——这三个不是同一个字段，也不该都要求填写。

规则：每个字段标注 `needed_by`（决策类型列表，或 `all`）。

```
字段必填 ⇐ 当前 decision_type ∈ needed_by
缺必填字段 → 定位线输出「信息不足」标注 + 警告，不崩溃、不编造
非当前决策类型的字段 → 留空即可，校验器不提示
```

由此，static 块里没有「全局必填」的字段，只有「条件必填」的字段。校验逻辑
（v0.2 第 6 步实现）先读 decision_type，再按 needed_by 集合验字段。

### 3.1 `strategic_focus` 主业方向清单

- **定位线步骤**：S5。路线标签 ∈ strategic_focus → 正常打分；∉ → 降级或排除。
- **形态**：字符串列表。**值域 = domain_lexicon 路线标签体系的子集**，禁止自由文本
  （自由文本导致「水处理」匹配不上「污水资源化」）。新方向先登记进术语表再引用。
- **needed_by**：all（S5 是门控步骤，所有决策类型都过）。
- **static / dynamic**：static。
- **敏感度**：L1（主业方向基本是公开信息）。
- **填法**：每条 = 一个术语表标签。

### 3.2 `capabilities` 现有能力清单

- **定位线步骤**：S3 适配度、S4 装置规模核对。
- **形态**：列表，每项含：
  - `name`：能力名，**值域 = domain_lexicon 能力术语表（新增，见 §8）**，禁止自由文本
  - `note`：规模/水平补充（可选；装置写量级，实验能力写可测指标类别）
  - `evidence_ref`：证据的**本地文件路径**（设备清单、资质证书），只写相对路径占位
- **needed_by**：中试立项 / 技术选型 / 示范工程 / 论文选题 / 标准预研 / 长期跟踪；
  **专利申请不需要**（专利布局不取决于现有实验能力）。
- **static / dynamic**：static 为主，新增装置时手动追加。
- **敏感度**：L2（能力清单本身是竞争情报，规模写数量级）。

**S3 匹配规程（粒度裁定）**：

| 项 | 规则 |
|---|---|
| 匹配粒度 | 三档：**有 / 部分有 / 没有** |
| 缺口呈现 | 单独一列写**文字**（缺哪项能力、差多少） |
| 成本估算 | **禁止**。缺口成本估算是让 LLM 编数字，与「不许编来源」是同一纪律问题。「缺什么」是客观事实可以写，「补缺花多少钱」交给用户判断 |

关键前提：路线能力要求由学术线从术语表派生，能力供给也必须从同一术语表选值——
两边在同一坐标系里，匹配才成立。这是 §8 能力术语表必须新建的原因。

### 3.3 `constraints` 约束块

| 子字段 | 步骤 | 形态 | needed_by | static/dynamic | 敏感度 |
|---|---|---|---|---|---|
| `budget_band` | S4 | 枚举：`<50万 / 50-200万 / 200-500万 / >500万` | 中试立项 / 技术选型 / 示范工程 | **dynamic** | L2 区间 |
| `staff_band` | S4 | 枚举：`≤2人 / 3-5人 / >5人`（可投入本课题全职当量） | 中试立项 / 技术选型 / 示范工程 | **dynamic** | L2 区间 |
| `external_collab` | S3 | 布尔 + 可选说明（接受外协/联合研发与否） | all | static | L1 |
| `timeline_expectation` | S4 | 枚举：`≤1年 / 1-2年 / 2-3年 / 不限` | 中试立项 / 技术选型 / 示范工程 | **dynamic** | L1 |

**dynamic 判定标准**（防凭感觉分块）：字段值变化频率 × 变化是否改变定位结果。
budget_band 年年变且直接改变 S4 → dynamic；external_collab 几乎不变 → static。

### 3.4 `decision_context` 决策语境块

- **定位线步骤**：S6 权重、S7 门槛。

| 子字段 | 步骤 | 形态 | needed_by | static/dynamic | 敏感度 |
|---|---|---|---|---|---|
| `decision_type` | S6 | 枚举（7 值）：`中试立项 / 技术选型 / 专利申请 / 示范工程 / 论文选题 / 标准预研 / 长期跟踪` | all | **dynamic** | L1 |
| `risk_posture` | S7 | 枚举：`保守 / 平衡 / 进取` | all | **dynamic** | L1 |

**为什么是 dynamic**：决策语境每次立项都可能不同，而 S6/S7 直接消费它——这正是
company_profile 分 static/dynamic 的存在理由：static 错了一直错，dynamic 错了下次改。

**权重表（裁定 D-3）**：代码内置，**不写进 profile**——权重是方法论不是数据。
但代码中的权重表必须带理由注释，注释是项目方法论的一部分。理由注释样例：

> 中试立项要回答的是「能不能做成 + 做出来是不是我们的」，因此技术价值与
> 我方适配合计占主导（各 25）；市场机会在中试阶段只做方向性校验（15），
> 留待示范工程阶段再上调——那时工程化投入与市场验证才是主要矛盾。

初始标定值见 §7。调整权重 = 改代码，审计轨迹留在 git。

### 3.5 `exclusions` 红线 / 否决项清单

- **定位线步骤**：S5。命中即「不建议」，无需后续打分。
- **形态**：列表，每项 = {`code`（稳定代号，如 EX-001）、`label`（术语表标签或关键词）}。
  **reason 不明文写，走 L3 代号映射**（§5）。
- **needed_by**：all。
- **static / dynamic**：**dynamic**（历史否决记录随立项累积，本身是高价值决策痕迹）。
- **敏感度**：**L3**，三约束与退回条款见 §5。
- **联动**：评审会新否决一条 → 记忆库 pending 流程 → 人工确认后写入 profile.dynamic。

### 3.6 `application_scenarios` 应用场景 / 转化对象清单

- **定位线步骤**：S5 转化承接——**裁定 D-2：不进矩阵，进报告结论的理由段**。
  矩阵是「路线 × 客观维度」，每格必须可比较；转化可行性是综合判断，与我方适配度
  高度重合，硬塞会打架，且诱导 LLM 每行都给「可行」。
- **形态**：字符串列表，自由文本（应用场景天然领域相关，不做值域约束）。
- **needed_by**：all，但**非必填、不可删**——不填则报告的理由段不写转化承接，
  矩阵照常出。
- **static / dynamic**：static 为主。
- **敏感度**：L2（客户/渠道信息属商业敏感）。

### 3.7 `production_line_compat` 产线兼容性（条件字段）

- **来源**：审查清单第 4 项压力测试。「选型」决策下，新技术的约束不是「我方会不会」，
  而是「能不能嵌进现有产线/工艺链」——这是与 capabilities 不同的判断。
- **形态**：文本或列表，描述现有产线/工艺链对新技术的硬性约束（接口、规模、工艺段）。
- **needed_by**：**技术选型**（此决策下必填）；其余决策类型留空。
- **static / dynamic**：static。
- **敏感度**：L2。

### 3.8 `patent_pool` 现有专利池（条件字段）

- **来源**：同上。「申请专利」决策需要知道自己手里已有什么，才能判断新颖性与布局。
- **形态**：列表，每项 = 专利号/申请号 + 一句话范围（本地真实文件可写全，profile
  里允许只写分类统计，如「发明专利 X 项，集中于 <术语表标签>」）。
- **needed_by**：**专利申请**（此决策下必填）；其余决策类型留空。
- **static / dynamic**：dynamic（专利池随申请/授权变化）。
- **敏感度**：L1-L2（专利本身公开，统计口径仍可模糊）。

## 4. 已淘汰字段（删减留痕）

按「定位线哪一步需要它」审查，以下字段**淘汰**：

| 淘汰字段 | 淘汰理由 |
|---|---|
| `organization_meta`（公司规模、性质、人数） | 答不出定位线哪一步需要。组织差异通过 `decision_context` 表达 |
| `business_model`（商业模式） | 同上。投入回报判断已在 constraints 与决策语境中间接覆盖 |
| `industry`（所属行业） | 与 strategic_focus 冗余；且行业是单值标签，装不下多主业 |

另有一条**反向纪律**：压力测试新暴露的字段（§3.7 / §3.8）只在「有明确 decision_type
消费者」时进入字段表，否则进候选池等待，不因为「某个样本里出现过」就长进结构。

## 5. 敏感度分级与 L3 机制（裁定 D-1：采用代号映射，附三约束 + 退回条款）

| 级别 | 含义 | 填法 |
|---|---|---|
| L1 | 公开或半公开信息 | 直接填真实值 |
| L2 | 竞争敏感但定位线必须要 | 填区间 / 数量级 |
| L3 | 高敏感（历史决策细节、客户名） | 代号映射 |

**L3 机制（三约束，全部满足才启用；任一做不到 → 退回「不记 L3 字段」）**：

1. **位置**：映射文件放 `knowledge/private/mappings.yaml`，`.gitignore` 单独盯
   `knowledge/private/`，不与 profile 同目录（已实装：.gitignore + check_sensitive.sh
   双层防护）。
2. **稳定**：代号一旦对应某理由，永不重编号（理由文本修订不改号，只改映射值）。
3. **无语义**：代号禁止携带任何信息（EX-001 ✓，EX-膜-001 ✗——后者从代号本身
   泄露被否决方向）。

退回条款：**三条做不到就删 L3 字段**——宁可少一个字段，不要一个会泄漏的字段。
当前仅 `exclusions` 的 reason 走 L3；未来新增 L3 字段须重新过三约束审查。

## 6. 机会定位矩阵的定义（裁定 D-2 后冻结）

矩阵 = 技术路线 × **5 个客观维度**，每格可比较、可追溯：

| 维度 | 来源 | 说明 |
|---|---|---|
| 技术价值 | 学术线 | 成熟度 + 新颖性综合 |
| 市场机会 | 市场线 | 竞争度反向（竞争越弱机会越大） |
| 专利自由度 | 市场线 | 壁垒可绕开性 |
| 我方适配 | S3 | 三档匹配 + 缺口文字列（无成本估算） |
| 投入可行 | S4 | 预算/人力/周期/装置规模核对 |

门控（不计权重）：S5 主业外 → 降级；红线命中 → 不建议。
判断行：S6 按决策类型权重加权 → S7 按风险偏好定「建议 / 观望 / 不建议 / 信息不足」。

**转化可行性不在矩阵里**。`application_scenarios` 的产出进报告结论的理由段，
作为「建议」或「观望」背后的综合论证，不占格。

## 8. 前置新增：domain_lexicon 能力术语表（工作量估算）

§3.2 的硬前提：能力名必须从术语表选值。现有 domain_lexicon 只有路线术语表，
**需新增能力术语表**：

```
CAP-xxx: {
  zh: 中文名,
  en: [英文同义词],
  category: 实验能力 / 装置能力 / 数据资产 / 资质 / 软件工具
}
```

- **种子**：从现有路线标签的能力要求抽取 20–30 条。
- **治理**：新能力术语走记忆库 pending 流程登记（与路线标签同一套）。
- **工作量估算**：0.5–1 天（含种子抽取 + 与存量路线标签对照查重）。
- **归位**：v0.2 实施顺序中插为 **Step 3.5**（定完两条线 schema 后、改造学术线前），
  因为它是学术线改造（路线要求结构化输出）的前置。
